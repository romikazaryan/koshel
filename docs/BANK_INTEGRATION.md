# Подключение банков, брокеров и крипто — план koshel

> Для пользователя и разработчика. Обновлять по мере прогресса Фазы 6.

**Последнее обновление:** 2026-06-07

---

## Зачем это нужно

Пользователь koshel хочет видеть **реальные траты и поступления** без ручного ввода и **без импорта CSV/PDF**. Единственный путь — **API с согласия пользователя** (OAuth / Open Banking).

---

## Рынок в России (2025–2026)

| Что происходит | Что это значит для koshel |
|----------------|---------------------------|
| ЦБ РФ развивает **Open API / Open Finance** (стандарты ФАПИ.СЕК) | Банки уже обмениваются данными **между собой** (T‑Банк «мультибанкинг», Сбер + T‑Банк) |
| С 2024–2026 идут пилоты «личного финансового ассистента» | Сторонним приложениям нужен **статус партнёра** или договор с банком/агрегатором |
| T‑API, Sber API — в основном **B2B** (расчётные счета юрлиц) | Для **физлиц** публичного «Plaid для всех» пока нет |
| ZenMoney синхронизирует через **свои плагины** в приложении | Обходной путь, не официальный Open Banking; юридически и технически хрупко |
| Plaid / Tink / TrueLayer | **Не работают** с российскими банками |

**Вывод:** koshel строит **инфраструктуру сейчас**, а первый **живой** банк подключаем после партнёрства или появления API для PFM у одного из топ‑банков.

## Архитектура (3 слоя)

```
┌─────────────────┐     OAuth / deep link      ┌──────────────────────┐
│  Приложение iOS │ ─────────────────────────► │  Edge Function       │
│  (экран банков) │ ◄───────────────────────── │  bank-oauth / sync   │
└─────────────────┘     JWT пользователя       └──────────┬───────────┘
                                                          │
                        ┌─────────────────────────────────┼─────────────────────┐
                        ▼                                 ▼                     ▼
                 financial_connections          financial_accounts      transactions
                 (+ secrets, service only)       (счета)                 source = bank
```

### Таблицы (миграция `20260607100000_financial_connections.sql`)

| Таблица | Назначение |
|---------|------------|
| `financial_connections` | Подключение к провайдеру (банк/брокер/крипто), статус, время синка |
| `financial_connection_secrets` | Токены — **только server**, не из приложения |
| `financial_accounts` | Счета / карты / брокерский счёт / кошелёк |
| `transactions.external_id` | ID операции у банка — **дедупликация** |

### Типы провайдеров (`provider_kind`)

| kind | Примеры | Этап |
|------|---------|------|
| `bank` | T‑Банк, Сбер, ВТБ, Альфа | **Сейчас** (инфра + партнёрство) |
| `broker` | T‑Invest, БКС, Финам | После банков |
| `crypto` | Bybit read-only, on-chain адрес | После брокеров |

## Юридика и безопасность

1. **Согласие пользователя** — явный экран «koshel получит доступ к операциям по счёту X».
2. **152‑ФЗ** — персональные данные и токены; политика конфиденциальности до публичного запуска.
3. **Токены** — только на сервере; в проде миграция в **Supabase Vault**.
4. **Отзыв** — удаление connection + secrets + опционально помеченных bank-транзакций.
